# Quick Wins Implementation Plan

## Goal
Implement the 6 highest-value quick wins from `suggestions.md` that require the least effort but deliver the most daily-driver improvement:

1. Session pinning (top-to-top sorting in session list)
2. Session export (Markdown)
3. SSE event inspector (debug mode)
4. Inline message timestamps
5. Developer quick actions (settings section)
6. Compact density mode

## Architecture Context

- **State management**: Zustand stores in `src/stores/` — `sessions.ts`, `settings.ts`, `events.ts`, `connections.ts`
- **Persistence**: `expo-secure-store` for settings and connections; pins would use SecureStore
- **SSE loop**: `events.ts` `connect()` iterates `client.global.events()` async generator
- **Session list**: `app/(tabs)/index.tsx` flattens sessions into group+item rows via `groupByDirectory`
- **Settings screen**: `app/(tabs)/settings.tsx` — reusable `SettingSection`/`SettingRow` components
- **Message bubbles**: `src/components/chat/MessageBubble.tsx` — memoized, renders role header, text, tokens
- **CodeBlock**: `src/components/markdown/CodeBlock.tsx` — already has copy action

## Decisions

- **Pinning storage**: Local-only in SecureStore (no `pinned` field on server `Session` type in `sdk.ts`). Sync is best-effort — pins survive restarts but don't sync across devices.
- **Export format**: Markdown only (JSON is lower value for a personal fork). Use `expo-sharing` share sheet.
- **SSE inspector**: Debug mode toggle in Settings → new `/debug/sse` route. Ring buffer of last 500 events in the events store.
- **Timestamps**: Relative time ("2 min ago") inline in message bubbles, absolute on long-press via clipboard copy. Reuse existing `formatTime` helper pattern from sessions list.
- **Developer actions**: New "Developer" section in Settings. Force reconnect calls `useEvents.getState().connect()`. Dump Zustand state serializes `useSessions.getState()` and `useConnections.getState()` to clipboard.
- **Density mode**: New `density` field in `settings.ts` (compact | default | comfortable). Applied via a `useDensity()` hook that scales padding/margins in `MessageBubble` and sessions list.

## Risks

- **Pinning persistence**: If user reinstalls app, pins are lost (SecureStore doesn't sync). Acceptable for personal fork.
- **SSE ring buffer memory**: 500 events × small payload ≈ negligible. No concern.
- **Markdown export fidelity**: Tool calls, reasoning blocks, and images need appropriate Markdown formatting. Keep formatting simple.
- **`expo-sharing` availability**: Already a dependency for notifications; sharing module is standard.

## Out of Scope

- Server-side pinning sync
- JSON export format
- Conversation branching
- Local LLM mode
- Tablet split-screen layout

## Notes

- Follow existing code conventions: use `const` over `let`, early returns, single-word variable names, no `any`, no `try/catch` where avoidable
- Use existing `SettingRow`/`SettingSection` components in settings screen
- Use `expo-sharing` for export (already installed for notifications)
- Use `expo-clipboard` for timestamp/long-press copy (already used in `[id].tsx`)
